# TVision Installation Handbook (Markdown)

Readable conversion of Sergio Sigala's `tvision.texi` (TVision 0.8, the UNIX port of
Borland's Turbo Vision 2.0). Original Texinfo preserved alongside as
`installation-handbook.texi`. Light editing only: Texinfo markup → Markdown, content
unchanged. This is the **prose** companion to the doxygen class reference — it
explains the runtime behaviour (keyboard / screen / mouse / events) that the PHP
port has to reproduce or replace.

## Overview

Turbo Vision (or TV, for short) is a library that provides an application framework.
With TV you can write a beautiful object-oriented character-mode user interface in a
short time.

TV is available in C++ and Pascal and is a product of Borland International. It was
developed to run on MS-DOS systems, but today it is available for many other
platforms (ported by independent programmers).

This port is based on the Borland 2.0 version with fixes.

---

## File structure (of the upstream package)

- **`doc/`** — all documentation.
  - `html/index.html` — main documentation page → links to both the *installation
    handbook* and the *class hierarchy documentation*.
  - `tvision.info` / `tvision.texi` — the installation handbook (this document):
    installation, keyboard handling, screen manipulation, environment variables,
    mouse support.
  - `html/{hierarchy,classes,annotated,files,functions,globals}.html` — the class
    hierarchy documentation (doxygen), describing each class, method and data member.
    Generated by annotating each class in its `.h` header and running doxygen.
- **`lib/`** — all library sources, both header (`.h`) and program (`.cc`) files.
  - `tv.h` is the only header an application needs to include. It pulls in the
    required TVision headers by looking at the `Uses_XXXX` macros: define a macro and
    the relevant header is included.
- **`demo/`** — a complete application (`demo`): predefined views, subclassing to make
  custom views, event handling, the online help system, and streaming views to/from
  streams.
- **`tutorial/`** — many simple examples; see its `README` (also reproduced in
  `examples/README.md`). `basicMakefile` is a template to build your own programs.
- **`tvhc/`** — the help compiler: translates a source help file into the binary form
  TVision uses internally.

## Portability issues

The TV library was originally written for the 80x86 processor — little-endian — and
the original library assumes this. Some code may not run properly on big-endian
machines, so full portability across Unix machines took effort. The port was changed
to run correctly on big-endian machines (tested on a PowerPC running Linux).

Another problem is the heavy use of the PC-specific character set. It looks nice on a
system console but can show annoying characters on a remote terminal or under an X
shell.

> **Port implication:** for PHP, the endian concerns are moot, but the **PC code-page
> (CP437) line-drawing/semigraphics** issue is central — modern terminals are UTF-8,
> so the port should map CP437 box-drawing glyphs to their Unicode equivalents.

## Keyboard

The `ncurses` library is used throughout TVision for keyboard input (and usually for
video output too). It gives terminal-independent input and optimized screen updates.
ncurses supports: output to windows and reading terminal input; control over
terminals and their I/O capabilities; some color manipulation; terminfo
capabilities; access to low-level terminal-manipulation routines.

Video attributes/colors can render characters underlined, in reverse video, or in
color where supported; line-drawing characters may be output. On input, ncurses
translates arrow and function keys (which transmit escape sequences) into single
integer values.

Under Linux a special output mechanism called **VCS** gives direct access to console
screen memory — noticeably faster than ncurses output (see Screen).

### Key combinations

- **FreeBSD:** `ALT` combinations aren't supported directly — emulate with `ESC`
  sequences. Press `ESC` then the letter within ~0.4 s (configurable in `system.cc`).
  To get `Alt-X`, press `ESC X`. `ESC` alone = press it twice or wait 0.4 s. `CTRL`
  and `SHIFT` combinations are also missing.
- **Linux:** `ALT` combinations work only from the system console, where the library
  detects `ALT`/`CTRL`/`SHIFT` via the Linux-specific `TIOCLINUX` syscall — so
  combinations like `kbCtrlLeft` are possible. On remote terminals / X shells these
  can't be detected; use the `ESC`-sequence emulation as on FreeBSD.

> **Port implication:** the PHP keyboard driver must decode terminal escape sequences
> into TV-style key codes (`kbEnter`, `kbF1`, `kbAltX`, …). Modifier detection beyond
> what the terminal sends in escape sequences (xterm modifyOtherKeys / kitty protocol)
> is the modern equivalent of the `TIOCLINUX` trick.

## Screen

### The importance of SIGWINCH

The `SIGWINCH` signal is always hooked, so the screen can be resized at runtime and
the application adapts itself — especially useful in X shells.

> **Port implication:** PHP should trap `SIGWINCH` (via `pcntl`) and reflow the view
> tree on terminal resize.

### Two drawbacks of ncurses

1. It can't output all 256 characters the 8-bit encoding allows, including the
   semi-graphical signs used by text-mode PC apps. TVision uses them all (frames,
   window icons, etc.), so an app may look graphically poor.
2. It's slow — slower on Linux console than FreeBSD; equally slow on other terminals.
   Noticeable on 486/low-end Pentiums.

Speeding this up requires low-level, OS-specific, non-portable trickery.

### The Linux way: virtual console mode vs remote mode

Linux has **VCS/VCSA** (virtual console system) devices giving direct access to
screen memory — much faster ("virtual console mode") and able to display all 256
characters with all colors, fixing problem (1). The conventional ncurses path is
called "remote mode".

Devices: `/dev/vcs0` (current console memory), `/dev/vcs[1-63]` (per console),
`/dev/vcsa[0-63]` (same, with attributes + a 4-byte header: lines, columns, cursor
x, cursor y). These may need root privileges.

**Conclusions on Linux** — every program can run two ways:
- *Virtual console mode* — fastest; auto-selected when started from the system
  console with write access to `/dev/vcsa*`; output goes straight to the display.
- *Remote mode* — used from a remote terminal / telnet / X shell / unprivileged
  console; output goes via stdout, much slower.

In any case, colors are used if the terminal supports them; otherwise a monochrome
palette with bold + inverse attributes marks the text.

### Two notes on FreeBSD

- FreeBSD has no VCS, but doesn't really need it — its ncurses output is moderately
  fast thanks to its screen-update technique.
- The last screen line is not used, otherwise the display scrolls up ("last
  character syndrome").

> **Port implication:** the VCS path is a Linux-console micro-optimization irrelevant
> to a modern PHP port. Target ANSI/`ncurses`-style output over stdout (the old
> "remote mode") as the single backend; treat truecolor + UTF-8 as the baseline.

## Mouse

Mouse handling varies a lot by OS (timing tweakable in `system.cc`).

- **FreeBSD:** requires the `moused` daemon. E.g. for a Microsoft mouse on COM1:
  `moused -p /dev/cuaa0 -t microsoft`. The `TVOPT` env var can change the cursor
  shape (`noarrow` → block pointer instead of arrow).
- **Linux:** requires **Gpm**, a mouse server for the Linux console providing cooked
  mouse events to text apps (tested with Gpm 1.18.1).

> **Port implication:** modern terminals report mouse via xterm SGR mouse mode
> (`\e[<…M/m`). The PHP mouse driver enables that mode and decodes those sequences —
> no Gpm/moused needed.

## Environment variables

Two env vars modify how TVision applications behave:

### `TVLOG`

Forces TVision to write a log file. e.g. `TVLOG=mylog` produces a log named `mylog`.
Assigning an empty string suppresses the log.

### `TVOPT`

A set of space-separated strings; valid values:

| Value | Effect |
|-------|--------|
| `cyrillic` | Enable Cyrillic character-set mapping (Linux + VCS only). |
| `latin` | Enable Latin character-set mapping (Linux + VCS only). |
| `noarrow` | Disable the arrow pointer (FreeBSD only); use the block pointer. |
| `nogpm` | Disable the Gpm mouse driver (Linux only); run without mouse. |
| `novcs` | Inhibit VCS for video output (Linux only); always use remote mode. |

Examples (Bourne shell):

```sh
export TVOPT=nogpm          # does not use Gpm
export TVOPT="nogpm novcs"  # disables both Gpm and VCS
export TVOPT=               # clears the variable
```

## Compiling TVision (upstream)

Autotools-based:

- `./configure` — detect system features.
- `make` — compile static + dynamic libraries into `lib/`; demo and tutorials are
  statically linked.
- `make install` — install to `/usr/local/include` and `/usr/local/lib` (default
  prefix `/usr/local`, override with `--prefix=PATH`; needs root; follow with
  `ldconfig`).
- `make uninstall`, `make clean`, `make dist` as expected.

`configure` options worth noting (they reveal optional capabilities): `--disable-acs`
(alternate char set), `--disable-8bit` (8-bit output), `--disable-linux-gpm`,
`--disable-linux-vcs`, `--disable-freebsd-mouse`, `--enable-russian`.

> Not relevant to PHP packaging (Composer), but the toggles document which features
> were considered optional/platform-specific.
